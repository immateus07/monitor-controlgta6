# Monitor universal v4.0

Atualização: envie monitor.py e produtos.json para a raiz do repositório, no mesmo commit. Preserve historico.json, requirements.txt e .github/workflows/monitor.yml. Os Secrets não mudam. Execute uma nova execução em Actions > Run workflow, com teste marcado para receber o relatório.

Para adicionar produtos, edite produtos.json. Cada objeto tem id único e estável, nome, modelo (ou vazio), preço máximo numérico, ativo, avisar_sem_estoque, avisar_pre_venda, consulta, termos_obrigatorios, termos_excluidos e links. Cada termo obrigatório deve aparecer; uma lista interna significa alternativas. Um modelo exato também pode identificar o produto; termos excluídos sempre vetam. Use links HTTPS de lojas permitidas. Não altere o id ao mudar apenas preço; use outro id ao trocar de produto. Separe objetos com vírgula. Não use vírgula após o último objeto. Comece com poucos produtos: 15 links e três tentativas de busca por produto; o workflow tem limite de tempo. Preço apenas em BRL, sem frete ou impostos. O domínio permitido não garante vendedor confiável. Consultas podem ser bloqueadas; isso não equivale a falta de estoque. Histórico v3 é migrado sem apagá-lo. Relatório manual não repete alertas já registrados; relatório diário após 8h de Brasília. Se quiser reenviar um alerta específico, confira o histórico primeiro, não o apague indiscriminadamente.
